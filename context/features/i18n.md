## Summary

Lightweight client-side i18n that fits this SPA-style app (no URL/locale routing): persisted locale atom, typed dictionaries with **English as the source of truth**, Arabic with full right-to-left support, and a one-tap EN⇄ع switcher in the Navbar.

## Architecture

```
src/i18n/config.ts        locales, Locale type, LOCALE_LABELS/SWITCH_LABELS, localeAtom (persisted "weather.locale"), nextLocale()
src/i18n/dictionaries.ts  en = source of truth (type Dict inferred); ar: Dict; getDictionary(locale)
src/hooks/useI18n.ts      { locale, setLocale, toggleLocale, nextLocaleLabel, t, dateLocale, dir }
src/components/LocaleSync.tsx  mirrors locale to <html lang dir> (rtl for ar)
```

- Parameterised strings are functions in the dict (`places.switchTo(city)`, `radar.title(coords)`, `nav.languageAria(next)`).
- Dates: date-fns `Locale` passed through `format(..., { locale })`; `safeFormat`/`safeFormatUnix` gained an optional trailing `locale` arg.
- RTL: `<html dir="rtl">` flips flexbox main axes automatically; targeted utilities converted to logical properties (`ms-auto`, `start-0`, `text-start`, `ms-1`) where physical sides would break. Remaining physical classes (`left-1/2 -translate-x-1/2` centering) are direction-safe.

## Coverage

All user-facing strings extracted: Navbar (labels/arias/date), detail tiles + compact row, hourly/daily headings, chart heading + series names, AQI levels/dominant/out-of, radar heading+iframe title, places chips arias, footer, error page, 404 page. API-provided content (weather descriptions, city names, upstream error messages) intentionally stays untranslated.

## Tests (+4 → 48 total)

- Key-structure parity: every locale has exactly English's key paths (recursive)
- Leaf validation: all leaves are non-empty strings or parameterised functions
- Arabic function entries return strings containing interpolated values
- `nextLocale` cycles en ⇄ ar

## Gotchas for future agents

1. **Adding a string?** Add it to `en` first, then `ar` — the parity test fails CI otherwise. Add it to BOTH.
2. **date-fns v2**: the `Locale` type comes from `'date-fns'` root, NOT `'date-fns/locale'` (that subpath only exports locale objects).
3. **AQI tuple indexing**: `aqi` is 1–5; index the keys array with `aqi - 1`.
4. RTL review checklist: `ml-*`→`ms-*`, `left-*`→`start-*`, `text-left`→`text-start` on anything user-facing.

## Out of Scope / Follow-ups

- More locales (add file + entry in `config.ts`; parity test enforces completeness)
- Localised numerals (Arabic-Indic digits)
- Translating server-provided OWM condition descriptions via weather-id mapping table
